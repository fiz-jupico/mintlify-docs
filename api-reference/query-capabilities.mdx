All `POST /v1/query/*` endpoints accept the same sorting, paging, and filtering
options in the JSON request body, alongside any endpoint-specific filters.

<Note>
Single-record endpoints are the exception. [Get a transaction
receipt](/api-reference/query/get-a-transaction-receipt) returns one transaction
by `transactionId` and `subMerchantId`, and ignores the options below.
</Note>

## Sorting

Sort by one or more fields. Prefix a field with `-` for descending order.

```json
{ "sort": "-createdAt,amount" }
```

## Paging

```json
{ "limit": 10, "offset": 20 }
```

- `limit` — maximum number of results to return. Defaults to `1000` when omitted.
- `offset` — number of results to skip before returning results.

## Filtering

Filter on any field of the queried resource. Exact-match filters are plain
key/value pairs. Comparisons are written as a string value with the operator
as a prefix:

```json
{
  "status": "succeeded",
  "amount": ">=100"
}
```

| Syntax | Meaning | Example |
|---|---|---|
| `">value"` / `">=value"` | greater than / greater than or equal | `"amount": ">=100"` |
| `"<value"` / `"<=value"` | less than / less than or equal | `"amount": "<50"` |
| `"!value"` | not equal | `"currency": "!USD"` |
| `"a,b,c"` or `["a", "b", "c"]` | value in list | `"currency": "USD,CAD"` |

<Warning>
Send comparisons and lists in the forms above. Object operators such as
`{ "$gte": 100 }` or `{ "$in": [...] }` are not supported: they are rejected
with `400` on amount fields and can fail with `500` elsewhere.
</Warning>

## Combined example

```bash
curl --location 'https://sandbox-platform.jupico.com/v1/query/transactions' \
  --header 'Content-Type: application/json' \
  --user '<apiUser>:<apiPassword>' \
  --data '{
    "sort": "-createdAt",
    "limit": 10,
    "offset": 0,
    "amount": ">=100"
  }'
```

<Note>
List Transactions always returns `succeeded` and `declined` transactions; a
`status` filter on that endpoint is ignored.
</Note>
